01 / 结论

会议形成的主线

机器人进入集中联调

本体已回长沙并完成检查。导航、遥操作、技能和 Agent 都要上机，朱博需协调时段，避免多人抢占设备。

平台能力开始接业务

AIOS/Agent 将提供十月底较完整版本；动态感知接口和快递场景也在开发，目标是形成可在真实任务中验证的组合。

职责和资源要落到纸面

数据采集规格、版本验收、设备预算、跨团队责任与刘星宇原岗位交接仍有明确缺口，需要跟进闭环。

一句话判断：

项目已经从“单项能力分别研发”推进到“多团队围绕真实机器人做联调”；近期最大风险不是某个模型单点效果，而是接口、设备时间、数据规格、版本验收和人员分工没有同步锁定。

02 / 项目全景

从模型到真实场景的工作链

01 · 大脑与数据

规划能力

汇总通用规划语料，准备约 20 万条任务监督/进度预测样本；训练后有提升，但评测主观性、进度预测偏高和个别标注问题待修。

02 · Agent 与感知

组织任务

平台提供 Agent Loop、工具和 Skill 接入；新宇负责场景侧联调。动态感知接口要适配，快递场景方案已评审。

03 · 技能与本体

做出动作

下蹲转腰运控模型可用但有高频抖动；Pico 遥操的关节旋转控制需优化。X2 已配强脑手，X3 计划适配自研商业小手。

04 · 导航与交付

现场跑稳

自定位修复已合入，绕障优化测试中 CPU 降约 20%；旧款 2A 仍需关注 CPU、ROS 消息堵塞和定位漂移。

工程与项目管理进展

  • 导航：

    需要现场验证中间版本，并评估资源占用；后续导航适配要同时考虑传感器、环境和运控差异。3.0 本体路线变化较大，可能触发算法升级。

  • 仿真预研：

    RoboDog 基线已跑通，下一步比较加入 Agent 前后的任务规划效果。这是预研支线，不等于已可用于商用交付。

  • 产品化和预研分开：

    领导要求当期产品化/商用事项写明交付目标；预研项目以获得可信结论为目标，不以“证明原假设正确”为目标。

  • 资源：

    实验室装修目标十月底完成，约 25 万元预算争取 11 月划拨；项目组需按真实项目需要明确 X3 数量、辅助设备和明年预算，而不是先按供应能力倒推需求。

04 / 可执行行动

建议你接下来这样推进

  1. 先把对接窗口建起来（当天）

    联系文生、艾鹏和感知接口负责人，约 30 分钟对齐：版本何时可部署、谁部署、测试设备/环境、API/工具契约、十月底交付定义。把“版本完整”拆成可验证条目。

  2. 做一张联调清单（当天至 1 天）

    用一条取快递主链路做最小闭环：发起任务 → Agent 规划 → 调用感知/导航/按键工具 → 状态回传 → 成功/失败判定 → 失败恢复或人工接管。区分模拟环境与真机验证。

  3. 明确接口和验收口径（1–2 天）

    对动态感知、Agent Loop 和 Skill 逐项写清输入/输出、超时、重试、取消、状态回报及错误处理。至少记录成功率、单步延迟、端到端耗时、人工介入率和失败类型；避免只看演示成功。

  4. 交接与职责并行处理（本周）

    约小广单独谈当前事项、代码/文档、未完成工作、后续联系人和交接截止时间；同时与艾鹏梳理既有 Agent 工具。需要负责人定夺的边界，整理成具体选项请求拍板。

  5. 将探索变成短周期验证（确认方向后）

    针对端侧自动化/模型能力选一个可观测的小问题，建立基线，做小规模实验并记录算力、延迟、稳定性和收益。先验证假设，不要把不清晰的缩写或概念直接扩成大任务。

  6. 每周同步风险和阻塞

    用“完成了什么、下个可验收结果、阻塞/需要谁决策、目标日期”四项更新；本体排期、平台版本、接口、采数硬件任何一项变化，都同步到联调台账。

一个适合你当前角色的周报模板：

本周交付：____；真机/仿真验证：____；指标：成功率 __ / 延迟 __ / 人工介入 __；未解决问题及责任人：____；下周验收点：____；需要负责人协调：____。

05 / 风险与待确认

下一次例会前最好闭环

版本日期和验收标准

平台口头计划十月底发布较完整版本，联调版本可能需平台人员部署。确认正式版与联调版差异、发布日和可验收功能。

机器人资源冲突

导航、姚超/遥操、文康/技能、Agent 都要上机；由朱博排表并指定单一设备调度人，记录每次版本、配置和测试窗口。

采数规格和依赖

数据格式、目标动作、硬件/手柄、标注和软件要求需尽快成文。会议希望 11 月上半月获得支持，但日期表述有错听，必须重新确认。

模型评测可信度

约 20 万条样本和指标提升仍需排除评测主观性、数据偏差及标注错误；保留独立测试集和明确判定标准。

本体与相机适配

X3、X2、7 自由度手臂、强脑手/自研商业小手和腕部相机是不同依赖。会议中的交期与配置有待采购和硬件方确认。

团队职责交叉

Agent、平台、模型、交付和原团队边界尚未最终定案；先把决策人、执行人、协作人和交付件写清，减少重复开发或无人接管。

06 / 关联前次沟通

把两次会议放在一条线上看

上一次录音是业务架构介绍，重点解释平台/Agent、大脑与小脑、机器人本体、遥操作采数，以及“取快递”如何由导航、按键、观察、电梯切层和抓取等工具组成。当时强调单项能力不等于端到端可靠交付。

这次周会把那张架构图推进到了执行层：十月底 AIOS 版本进入联调，感知接口与快递场景进入开发，机器人已回现场；与此同时，硬件排期、数据规范、失败恢复和多团队分工成为实际瓶颈。也就是说，前次会议回答“系统由什么组成”，本次回答“团队怎样把模块接起来并在本体上验证”。

首次录音中讨论的 Agent 调工具、状态观察、网络/异常兜底，在本次会议中对应到 Agent Loop 版本、动态感知接入、快递系统和真机联调。前一次关于具体模型/世界模型是否已部署并未获得确证，本次会议也没有新增证据，不能把研究用语等同于当前产品能力。
