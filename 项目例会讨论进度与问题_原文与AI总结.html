详细内容整理

00:26–01:20｜本月目标与会议范围

开场提到 AIOS 相关人员尚未到会，随后按遗留任务跟踪、当前进展两条线推进。本月目标为电梯场景端到端交付，同时完成快递场景的前期算法验证；发言者说本月还剩一周，需要各子项加速。该相对时间来自会议原话，不能自动视为整理当月的正式截止日。

01:20–02:27｜电梯内网络中断与导航启动延迟

导航同事反馈，机器人进入电梯后连不上内网，这是导航及 Agent 整体串通的最大问题之一，计划当天下午找网络同事处理。另外，自研导航接到指令后约等 6～7 秒才开始动作；此时的问题首先是启动等待，而非只看行走速度。

02:27–04:11｜把“发令不动”和“走得慢”分开定位

导航侧此前收到的是进电梯行走慢的反馈，现场进一步澄清启动等待与移动慢都存在。周围障碍会触发速度限制，电梯口可能被认为是障碍区域。团队希望起步在约 1～2 秒内响应，理由是现场测算电梯门可能仅等待约 2～3 秒就关闭。讨论提出调整障碍附近限制、提高起步与移动效率，但还需定位原因；这些时间是现场观察与期望，不是通用电梯参数或已实现指标。

04:11–05:01｜当天下午联调与频繁进出的定位问题

计划由现场导航对接人与导航算法同事约当天下午验证。导航侧还发现反复进出电梯时定位容易出问题，已有通过参数调整的修改，想一起复测。录音中姓名有“向博/项博/向波”“伟超”等近音，正式协作名单应按群内联系人确认。不能把“已改参数”写成实机问题已经解决。

05:01–06:00｜遥操设备到场、采数流程与培训

遥操团队人员预计当天下午到长沙，头盔及设备随身携带，外骨骼已寄出。此前已在 A2 上调过，接下来要在现有本体上验证。之前的时延问题定位为路由器问题，需要在长沙再试。希望做遥操加采数端到端功能验证及培训，现场人员和相关对接方再安排时间。“姚超/要操/素材”等结合上下文分别按遥操、采数理解。

06:00–08:29｜刘星宇：Agent 联测、模型交付及进度口径

主持人请星宇说明电梯端到端还有什么问题、需要哪些支持。他反馈并非只测导航，而是由 Agent 下发指令、带着导航一起测；已测部分流程可走，但完整链路卡在电梯网络。意图感知模型版本尚需提供，拿到后会测，并继续与导航同事联调。有人追问近一周进度及智能体测试情况，现场补充这段时间还在处理七自由度及按按钮相关调试；网络与技能尚未打通，不能完整做端到端和相关时延测试。关于意图模型，有人澄清之前已经测过，过去由 AIOS 团队部署、业务方调用，现在准备利用本地机器自行部署，方便测试；因此新任务是获取明确版本并本地复测，不应表述成从未做过模型测试。

08:32–10:24｜实验室与平台复用的总体判断

实验室仍在通风，导轨相关线缆过长的问题已调整。平台复用分为功能复用与本体复用：家庭、商业的大脑与云平台能力较通用，跨楼层导航也可共享；当前基础运控主要由本体厂商提供。按按钮、取快递等家庭操作技能在当前商业规划中未涉及，所以这里的“不可复用”也有场景不需要的含义。总体判断是硬件无关模型更易复用，与硬件绑定的部分主要复用调试经验，并不意味着完全无需适配。

10:24–11:36｜大脑、语音、遥操的迁移差异

电梯感知与任务规划模型被认为硬件关联较弱，估计可复用程度在 90% 以上；语音约 75%，主要差异在不同 SDK 获取音频、图像的接口。遥操因 X2/叉二 与 X3/叉三构型差异较大，需要重新适配，口述可复用程度为零，但打通流程及熟悉厂商接口的经验可以帮助提速。这些百分比是会议估计，没有统一计算标准。

11:36–14:01｜按钮、取快递、运控、AIOS 和导航如何复用

按按钮当前偏规控方案，视觉分割、tracking、手眼标定等思路可复用，仍需处理 SDK 与硬件差异。取快递拟通过遥操采数、筛选、训练模型，换本体后数据和构型差异明显，口述可复用程度约 30%，但 codebase、训练流程、采数与筛选经验可复用。基础运控依赖官方能力，本体接口差异需导航与运控协作。AIOS 业务侧的 skill、工具及平台可复用程度较高，可能做小幅调整。导航算法和方案可共享，但本体参数与接口要重新适配；此前已从其他本体迁移过，可沿用经验。

14:01–18:22｜迁移规划与 X3 麦克风底噪

会议提出下一年度 1 月开始 X2 到 X3 迁移，第一季度完成相关适配，约 3 月整体使用 X3，并与商业共用本体。语音团队反馈 X3 自带麦克风降噪效果不好，电机噪声造成明显底噪；手持麦克风影响较小，可作为现阶段替代。麦克风据称由己方指定后安装，厂商仍在处理，尚未反馈最终降噪结果。主持人要求相关项目同事和硬件接口人共同跟进，希望发货时语音硬件已可用，家庭和商业一起对齐；人员近音需核。

18:22–20:23｜遥操迁移资源、URDF、手与到货计划

遥操团队询问 X3 接口、URDF、何时有机器、在哪里调试以及手部安排。回复称 URDF 应该已有，但需再确认并索取。建议先在上海调，因已有一台，十二月初计划再到三台，长沙估计一台、上海估计两台；地点仍可再商量。先使用强脑手，后续再考虑其他手。遥操迁移可能十二月中下旬开始，要求十二月需求排期不要遗漏。采购流程被说到已走某审批节点，但“YMA”缩写不清，只能确认后续还需正常采购发货。

20:23–21:55｜任务规划数据、SFT/强化与视频子任务标注

大脑侧说明按钮模型先独立调，后续再联调；部署方式已与星宇沟通。任务规划已整理 10 万多条语料，做过 SFT 与强化相关增训，报告性能改善；更大模型及行业 baseline 仍在测试，希望下周再沟通。视频子任务标注工具也在优化流程，发言者称某 Flash 模型做内容理解后超过此前英伟达方案。原稿“千问3.8 Flash”“Laura/LASS”等名称不可靠，未提供指标与同口径结果，因此不能据此确认具体模型或行业优劣。

21:55–24:17｜按钮技能迁到新手臂，流程已通但精度和手型待优化

按钮技能近两周迁到新手臂，能以相对合理手型完成动作流程，但仍需改善时延与末端误差。强脑灵巧手除拇指外其他四指为软关节，按压时可能被顶弯，需要手指略朝上、用指腹按。新升级的七自由度/腰部相关关节与仿真 URDF 不完全一致，出现厘米级误差；厂家八月更新过手模型，而本体现有模型可能仍旧，手指关节误差口述为一两厘米。仿真中流畅的按压效果尚未在整机充分复现，计划对齐模型后继续提高精度。具体哪一关节与自由度的对应关系需查硬件资料。

24:17–26:23｜更新手部 URDF、重新标定相机与快递仿真

按钮精度需更新 URDF 后进一步测。希望借遥操团队到场获得新模型；遥操与按压的精度要求不同，按压对厘米误差更敏感。相机多次调整后有松动，需要固定位置并重做外参标定。技能同事判断月内可跑通流程，但不能保证精度，需如实保留限制。快递拿取在仿真平台已有进展，真机仍需遥操部署与整机标定；会议希望本周先在另一平台/本体上尝试，原稿“松林/丛林”不确定，不能改成正式产品名。

26:23–27:37｜运控协助导航与 PICO 全身跟踪预研

运控同事正协助星宇做厂商本体的建图、导航，仍有网络与时延问题。另将此前训练的全身运控模型与 PICO 系统打通，在仿真中观察到跟踪效果较好，也可展示倒地后起身，但双脚较高离地、跳跃效果不理想，推测与训练有关。正在尝试部署到实机；录音未证明实机已完成起身或跳跃。

27:37–29:11｜刘星宇：两套导航已接测，先获取按钮脚本

星宇汇报已把公司自研导航接进 Agent 环境测试，也对厂商导航建图并测试。若按钮动作已经能执行，希望技能同事先提供脚本，以便接入 Agent，检查动作调用及相关时延；这不要求先把按压精度完全优化好才开始接口联测。技术预研方面，上周尚未开展，之后想看某项缩写相关内容，原稿“RSF”不明。网络解决后，要测电梯内部重定位、位置点漂移与纠正，以及按完按钮后出电梯；当前这些受断网影响尚未测。主持人负责跟网络，现场导航同事继续跟导航，只需把网络联系人发给负责人。

29:11–31:46｜AIOS 历史缺陷、前端反馈与耗时判断

星宇说此前发现预加载步骤可能改变提示词、新会话带入旧上下文影响 Agent 流程，这些问题据称在十月已由对应同事解决。轨迹曾可在前端会话页面查看；当前明确提出的优化是下发任务后页面应反馈中间步骤、关键节点和结果，避免没有可见反馈。他粗略统计 AIOS 自身开销较小，口述在几十毫秒至约百毫秒量级，主要时间在模型和导航，因此此刻优先优化前端可见性。这里是局部测量和当时判断，并非整个系统端到端已达该时延。后续仍需串步骤并继续反馈平台问题。

31:46–33:47｜新决策模型仅用于意图分类，刘星宇需获取部署

主持人把继续串联和意图模型时延测试列为本月主要事项。AIOS 同事说明已在机器人上调意图模型、提示词及耗时，新增决策模型用于降低此前意图分类耗时。星宇追问用途，确认只针对意图分类，而非替换所有任务规划模型；现场也提到动作 Agent、对话 Agent 两类。星宇表示拿到后部署测试，若尚未收到，下午联系提供模型的同事索取。原稿“GV”“C”等缩写不清，不能确认为具体架构或型号。

33:47–35:04｜语音已通，VIP 识别被摄像头启动问题阻塞

多模态团队说语音流程已联调打通，但没有专门测时延，只有简单体验。VIP 识别方面，之前摄像头正常，当前设备未启动，尚未完成联调，需要本周找现场人员配合恢复摄像头，再调 VIP 能力。因遥操和技能也占用机器人，建议在大群提前说明，一般提前一天安排，避免同机冲突。“心雨”可能指另一位同音同事，未将该任务全部认定为刘星宇独立负责。

35:04–36:25｜刘星宇：语音时延要从体感变成实际测量

主持人要求测语音对话时延。星宇询问使用秒表还是后台接口；语音同事说端到端通常靠录音。他希望借轨迹或接口测，但指出语音是 OS 外部部分，可能不完整经过 AIOS 轨迹。最后同意先用录音或秒表做不依赖平台条件的初测，再线下对齐详细方法。星宇说体感语音不慢，但没有具体数值，所以不能以体验替代正式测量。这与另一段语音技术讨论中的 VAD/ASR/TTS 分段分析直接关联。

36:25–37:18｜遥操采数本周目标

遥操团队表示头盔和外骨骼适配开发已完成，上次在上海发现的抖动已解决，采数已部署。现场人员已出发/到场，本周计划把 HTC 与外骨骼联调完成，作为此次到场主要目标。前面提到 PICO 的是另一条运控预研，不能把所有头盔讨论混成同一设备。

37:18–39:03｜最后明确的卡点、手部适配与十二月规划

导航侧再次确认两个问题：进电梯慢、频繁进出后容易丢定位，安排当天下午一起修和验证。手部整改预计月底产出四只右手，先适配一只，再安排遥操及后续地点；数量、型号和是否最终交付仍需后续确认。会议收尾明确负责人跟电梯网络、导航同事对导航、星宇对意图模型、技能继续串通、现场同事对接遥操采数来访人员。全员准备十二月规划，并提前考虑 X3 适配；录音末尾停在“提前做一些……”附近，没有完整后续。
